# Tasks

Shape: TDD. The change is about five pass/fail cores: the proposal check, the one-open-proposal rules, the mapping of `claude agents` output to the session list, the announcements, and the cleaning of a session's screen. Section 1 writes their failing tests together with the tests of the runner, the manager, the server, the commands, the page and the prompt, and section 2 makes them green. Section 3 is one whole-suite check. `## H0.` and `## H1.` hold the steps only a person can take; their lines carry `[human]` or `[manual]` in place of a checkbox, so neither OpenSpec nor ship tracks them.

Order. This change is built on `add-voice-ui`. Every file it edits under `lib/voice/`, `lib/spawn.mjs` and the `test/voice-*.test.mjs` files is created by that change. Do not start section 1 before `add-voice-ui` is implemented and archived (H0.2).

Known test pins this change alters, each updated in the section 1 task that names it. They are named by what they pin, because `add-voice-ui` moves their line numbers: the command list in `test/cli.test.mjs` (twenty-one, now twenty-three, `propose` and `sessions` after `voice`); the cap list and count in `test/cli.test.mjs` and `test/limits.test.mjs` (sixteen, now twenty-one); `ALLOWED_TOOLS` character for character in `test/voice-engine.test.mjs`; the route list in `test/voice-guard.test.mjs` (eight paths, now thirteen); in `test/voice-server.test.mjs`, the case that a `tool_result` sends no event; and in `test/voice-prompt.test.mjs`, the prompt cases "five commands and no other" and "the draft rule naming Claude Code"; and in `test/voice-page.test.mjs`, the controller case that every final transcript is a turn. The rule for any further pin: an assertion that pins a meaning the delta specs change is updated in the task that changes that meaning, never during a remediation stage, and the update names the assertion and the requirement it now pins.

Shared values. `LIMITS` in `lib/limits.mjs` gains five keys at the end and one changed description (2.1); its readers read caps by name and have no task (`lib/agent.mjs`, `brief.mjs`, `collect.mjs`, `context.mjs`, `derive.mjs`, `narrate.mjs`, `next.mjs`, `record.mjs`, `remote.mjs`); the places that enumerate every cap are the two test pins above and the README table (2.13). `ALLOWED_TOOLS` (2.6) is read by `engineArgs` in the same file, pinned by `test/voice-engine.test.mjs` (1.1), and repeated by hand in `lib/voice/prompt.md` (2.9) and in the README's `voice` bullet (2.13). The reducer's effects and the engine's events (2.6) are read by the server (2.11). The event names of `GET /events` are written by the server (2.11) and read by `lib/voice/page-logic.mjs` (2.10); both take them from the `voice` and `voice-sessions` deltas. The guard's routes (2.8) are read by the server (2.11). `say(text, done)` (2.7) is called by the server (2.11). `createController` gains `get` and `timers` (2.10): `page.js` in the same task is its one caller. `SESSION_PREFIX` and `sessionName` (2.3) are read by the list filter (2.5) and the start (2.5). `callReason` (2.5) words every failed `claude` call for the server (2.11) and for `dial sessions` (2.12). The usage text (2.12) is copied by hand into the README (2.13). Every export a test imports is named in design §11 Interfaces; a task that needs another shape changes the design and the test in the same task and says so.
