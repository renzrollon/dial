# Tasks

Shape: TDD. The change is about four pass/fail cores: the gear geometry, the scene (what each part of the movement does for a given model and time), the frame budget, and the capture note rules (cleaning, the title, the file name, the refusals). Section 1 writes their failing tests together with the tests of the page, the prompt, the server, the command and the caps, and section 2 makes them green. Section 3 is one whole-suite check. `## H0.` and `## H1.` hold the steps only a person can take; their lines carry `[human]` or `[manual]` in place of a checkbox, so neither OpenSpec nor ship tracks them.

Order. This change is built on `add-voice-ui` and `add-voice-orchestrator`. Every file it edits under `lib/voice/` and every `test/voice-*.test.mjs` file it edits is created by one of them. Do not start section 1 before both are implemented and archived (H0.2).

Known test pins this change alters, each updated in the section 1 task that names it. They are named by what they pin, because the base changes move their line numbers: the command list in `test/cli.test.mjs` (twenty-three, now twenty-four, `capture` after `handoff`); the cap list and count in `test/cli.test.mjs` and `test/limits.test.mjs` (twenty-one, now twenty-two); `ALLOWED_TOOLS` character for character in `test/voice-engine.test.mjs` (seven entries, now eight); the route list in `test/voice-guard.test.mjs` (thirteen paths, now sixteen) and its case that the four static paths need no token (now seven); in `test/voice-server.test.mjs`, the case that serves the four static paths (now seven) and any case that compares the `proposal` event of an open proposal as a whole object (it gains `seconds` and `secondsLeft`); in `test/voice-proposals.test.mjs`, any case that compares an open proposal as a whole object; in `test/voice-page.test.mjs`, the prompt case "seven commands and no other" (now eight), the text checks that read `page.js` and `page-logic.mjs` (now the five served scripts), the remote-address check over the four page files (now seven), and the recording `view` of that file, which gains `stage`, `status` and `muted`; and the pack list in `test/plugin.test.mjs`, which gains three files. The rule for any further pin: an assertion that pins a meaning the delta specs change is updated in the task that changes that meaning, never during a remediation stage, and the update names the assertion and the requirement it now pins.

Shared values. `LIMITS` in `lib/limits.mjs` gains one key at the end (2.1); its readers read caps by name and have no task (`lib/agent.mjs`, `brief.mjs`, `collect.mjs`, `context.mjs`, `derive.mjs`, `narrate.mjs`, `next.mjs`, `record.mjs`, `remote.mjs`); the places that enumerate every cap are the two test pins above and the README table (2.11). `ALLOWED_TOOLS` (2.7) is read by `engineArgs` in the same file, pinned by `test/voice-engine.test.mjs` (1.4), and repeated by hand in `lib/voice/prompt.md` (2.7) and in the README's `voice` bullet (2.11). The list of served scripts is written by the server's loader and the guard's routes (2.8), and repeated in the pack list of `test/plugin.test.mjs` and the script lists of `test/voice-page.test.mjs` (1.2). The open proposal's object (2.6) is sent by the server as the `proposal` event, at a status change and to a connecting page (2.8), and read by `lib/voice/page-logic.mjs` (2.9), which hands the two numbers to the stage. The stage facts (`view.stage` changes) are written by the controller (2.9) and read by `reduce` in `lib/voice/scene.mjs` (2.3); both take them from design §14 Interfaces. `createController` gains `screen`, and `view` gains `stage`, `status` and `muted` (2.9): `page.js` in the same task is its one caller. `fakeTimers()` gains `now()` (1.4); every existing caller keeps working. The captured text has one canonical form, cleaned and then redacted once in `capture()` (2.5): the title, the file name, the note's bytes and the printed `text` all read that form, and the length check reads the cleaned text before redaction. The usage text (2.10) is copied by hand into the README (2.11). Every export a test imports is named in design §14 Interfaces; a task that needs another shape changes the design and the test in the same task and says so.

Angles. Code uses radians and the specs speak in degrees. A test converts the spec's figure and compares with a tolerance of 0.000000001.
