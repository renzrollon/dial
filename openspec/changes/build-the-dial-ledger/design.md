# Design

## Context

See `proposal.md` — Why. The repository holds the first change's output: `bin/dial.mjs` (shell, per-command option table, `fail()` as the only stderr writer, `main()` returning the exit code), `lib/home.mjs`, `lib/registry.mjs`, `lib/limits.mjs`, `lib/frontmatter.mjs`, `lib/settings.mjs`, `lib/doctor.mjs`, and a test harness (`test/helpers.mjs`: `tmp`, `makeHome`, `runCli`, `snapshotTree`, `makeGitDir`, `makeVault`). Every lib function is pure with respect to the process; only the bin touches stdout, stderr and the exit code. This change keeps that split and adds the pipeline on top.

Constraints unchanged from the first change: Node 22+, zero runtime and dev dependencies, macOS only, one owner. New constraint: every subprocess and every network call is optional and its absence is one `unobserved` value, never a crash (epic principle 1).

## Goals / Non-Goals

**Goals:**
- One vocabulary — the fact, the item, the state, the note — shared by every module, so the ten new capabilities are specced against the same shapes (D55).
- Deterministic derivation: the same disk yields the same notes, byte for byte, and a rebuilt vault equals the old one except the two preserved sections.
- Every write into a vault passes one boundary check against the registry, and nothing Dial writes is ever deleted.
- Hooks never block a session and never create files outside a registered repo's vault and the Dial home.
- Tests pin the state machine and the renderer before they exist (the TDD red wave covers exactly those two modules).

**Non-Goals:**
- No change to Interlock, Escapement or Checkpoint (the `Result:` marker is an Interlock change, epic D6).
- No Obsidian CLI dependency: direct file writes are the only write path (D22); the CLI is probed by doctor and used by nothing.
- No cloud model, ever, for the narrative fallback (D25).
- No SQLite, no server, no watcher daemon beyond a polling `dial watch`.

The lib stays pure: every module takes `env`, paths, data and injectable `exec`/`fetch`/`now`, and returns data or `{ ok: false, reason }`. `bin/dial.mjs` keeps the single `fail()` writer and adds sub-dispatch for `vault init` and `agent install|uninstall|status` in Escapement's shape (`vault needs one of init`, `unknown agent subcommand: X`).

### The fact (D55)

Every observed value is a **fact**: `{ value, evidence }` when observed, `{ value: null, unobserved: '<reason>', evidence? }` when not. `evidence` is one string naming the file, command or field the value came from (`gh pr view 38: OPEN`, `.claude/ship/runs/7a58….jsonl run-halt 2026-11-09T16:22Z`). The renderer prints an unobserved fact as `unobserved` in frontmatter and `unobserved: <reason>` in the State table. A missing optional file (no `merge-confidence.json`, no `manual-test-plan.md`, no `interrupted/` note) is an observed absence — value `absent`, evidence `<path>: absent` — and only a missing source root (no `git`, no work tree, no `openspec/`, no Escapement home, no sessions directory) or a missing binary is `unobserved` (D70). Nothing in `lib/` ever substitutes a default for an unobserved fact; a collector that cannot answer returns `unobserved` with the reason (`git: not on PATH`, `~/.escapement: absent`, `no openspec dir`, `gh: not authenticated`). This is epic principle 1 made a type.

`RepoFacts` is the per-repository bundle, one sub-object per source, every leaf a fact (`F<x>` below is `{ value: x, evidence } | { value: null, unobserved, evidence? }`). The sketch is the contract the parallel collectors (3.2–3.7), `collect` (3.8) and the `derive` fixtures (1.1) share; 2.1 writes it as a JSDoc typedef in `lib/facts.mjs`:

```text
RepoFacts = {
  repo:       { name, path, realPath, vault, host }
  git:        { branch: F<string>, detached: F<bool>, dirty: F<int>, ahead: F<int>, behind: F<int>, stash: F<int>,
                inProgress: F<'rebase'|'merge'|'none'>, unmerged: F<string[]>, worktrees: F<{ path, branch }[]>,
                lastCommit: F<{ sha7, head, date }> }
  openspec:   { active: F<string[]>, archived: F<{ name, date }[]>,
                changes: { [name]: { tasks: F<{ done, total }>, manualTest: F<'absent'|'present, no result'|'pass'|'fail'>,
                                     needsHuman: F<string[]>, checkpoint: F<'absent'|'approved'|'returned'>, lastMtime: F<iso> } } }
  interlock:  { run: F<{ runId, change, ended, halted, closedAt, stateHome }|'absent'>,
                stages: { [change]: F<{ pid, alive }> }, waves: F<{ done, total }>, terminal: F<{ type, reason, ts }|'none'>,
                interrupted: F<{ runId, change, at, file }[]>, merge: F<{ change, verdict }|'absent'>,
                outcomes: { [change]: F<{ commit, mergeVerdict, ts }> }, settle: F<{ surviving, head, file }|'absent'>,
                reviewArtifacts: { [change]: F<{ blockers, file }> }, resumeCards: { [change]: F<string> },
                trajectoryTs: { [change]: F<iso> }, drift: F<{ unarchived: string[], broken: F<int>, aging: F<int> }> }

}

```

`NoteView` is what `readNotes` (4.1) returns, parsed with `lib/note.mjs`; `derive` receives it already parsed and never parses a note, so 2.1 does not depend on 2.2.

### Collectors (`lib/sources/*`)

**Subprocesses** go through `lib/subprocess.mjs`: `execFileSync` with `timeout = subprocessTimeoutSeconds × 1000`, `stdio: ['ignore','pipe','pipe']`; `ENOENT` is `{ missing: true }`, a timeout or non-zero exit is `{ ok: false, code, stderr }`. `exec` is injected so every source test runs on canned output from `test/fixtures/<source>/`; `test/cli.test.mjs` adds one real-git run guarded by `{ skip: !gitOnPath }`.

**git** runs five commands in the repo: `rev-parse --abbrev-ref HEAD` (`HEAD` means detached; the short sha comes from `rev-parse --short HEAD`), `status --porcelain=v2 --branch` (dirty = entry count; `# branch.ab +n -m` gives ahead/behind; `u` entries are unmerged files), `stash list`, `worktree list --porcelain`, `log -1 --format=%H%x09%cI`. In-progress state is the existence of `rebase-merge/`, `rebase-apply/` or `MERGE_HEAD` under `git rev-parse --git-dir`. A directory that is not a work tree, or a missing `git`, makes every git fact `unobserved`.

**openspec** is pure filesystem: active changes are the directories under `openspec/changes/` other than `archive`; archived ones match `archive/<YYYY-MM-DD>-<name>/`; `tasks.md` is parsed with the same checkbox shape Interlock and OpenSpec read (`- [ ]`/`- [x]`, any single marker, done only on `x`/`X`); `manual-test-plan.md` presence and a `^Result:\s*(pass|fail)` line; `decisions.md` rows with class `needs_human` (the five-column ledger of `shared/DECISION-LEDGER.md`); `checkpoint.json` `decision.state`. No `openspec/` directory → the whole source is `unobserved: no openspec dir`.

**interlock** reads, in this order and each optional: `.claude/ship/run.json` (gated on `schema: interlock.run/1`), `.claude/ship/<change>/stage.json` plus `process.kill(pid, 0)` for liveness, `state.json` and `plan.json` for waves done of total, the trajectory `runs/<runId>.jsonl` (gated on `interlock.ship-run/1`, unknown `type`s skipped) for the terminal line, `interrupted/*.json` (every note with its `runId`, `change` and `at`; the state model decides which counts, D74), `merge-confidence.json`, `outcomes.jsonl` (last record per change), `settle/review-r<N>.json` (newest N, `surviving.length` and `head`; the record names no change, so its findings belong to the change the checked-out branch is attributed to, and only while `head` is the checked-out commit, D73), `.claude/metrics/review-artifacts-<change>-*.json` (newest, blocker count = findings with `severity: "blocker"`), `.claude/handoff/ship-<change>-<runId>.md` existence. When `run.json.stateHome` is set the trajectory, outcomes, metrics and handoff are read from there. `interlock drift --json` runs only from `sync` (D33) and only when `interlock` is on PATH; the drift fact is `unarchived` (the change names), `broken` and `aging` (the lengths of `stale.broken` and `stale.aging`, each `unobserved: interlock drift: <stale.reason>` when `stale.skipped`), and `orphans` is not read, because Dial never passes `--changed` (D75). The test fixture is a captured real reply.

**escapement** resolves `ESCAPEMENT_HOME` with Escapement's own rule (trim, tilde, default `~/.escapement`); an absent home makes every field `unobserved: ~/.escapement: absent` with exit 0 (the reason is always `<home>: absent`, with the home `~`-collapsed). Entries are matched to a registry repo by `path.resolve` equality of `entry.repo`, then by `realpathSync` of both (D61); the state is the directory name with the duplicate rule above; the newest `observation` line for the entry in today's and yesterday's UTC journal files supplies `class`, `category`, `reason`, `runId`. Dial never executes `escapement`.

**sessions** derives the slug from the registered path and, when it differs, from its real path too (Claude Code slugs its physical cwd, D77), lists depth-1 `*.jsonl` under `~/.claude/projects/<slug>/` and under every `<slug>--claude-worktrees-*` directory (and the slugs of the repo's linked worktrees from git), takes the newest mtime, and excludes the file named by the current `session_id` when one is given (`dial brief --session <id>`, set by the SessionStart hook) because the newest file is the live session (D28).

**github / gitlab** run only under `--remote` and only for the registry's `host` (D47): `gh pr view <branch> --json number,state,url,mergeable,mergeStateStatus,reviewDecision,isDraft,mergedAt,updatedAt,headRefName` and `gh pr checks <branch> --json name,bucket,state,link` (exit 8 is still JSON); `glab mr view <branch> -F json` and `glab ci status -b <branch> -F json`. "No PR" is an observed `null`; a PR with no checks (`[]`, or `gh pr checks` exiting non-zero with `no checks reported on the '<branch>' branch`) and a branch with no GitLab pipeline are an observed `ci: none`, from replies pinned off the real binaries (D81); an auth or rate-limit failure is `unobserved: gh: <first stderr line>`. `lib/remote.mjs` writes `$DIAL_HOME/cache/remote/<repo>.json` (`dial_schema: dial.cache/1`, `fetchedAt`, `host`, `branch`, `pr`, `checks`) after a fetch and reads it otherwise; a cached fact's evidence ends with `as of <fetchedAt>`; a failed fetch keeps the previous cache, serves `pr`/`ci` from it, and reports the failure on a separate `remote` fact, so a note never flips between cached and unobserved on an agent tick (D71). The cache is written only when every command in the fetch returned a result, and never under `--dry-run`. `next` and `brief` never fetch.

### The state machine (`lib/derive.mjs`)

`derive(facts, { now, limits, notes })` is pure and returns `{ items, repo }`. `notes` is the `NoteView` of what the vault already holds for this repo (parsed frontmatter, `## Next` items and narrative entry headings), because two human-owned signals live only there: the `dropped` marker (D35) and the manual-test checkbox (D34).

**One item per change.** Every active change and every change archived within `archivedKeepDays` is an item. The state is the first row of the epic's table whose signal is present, in this order, with the fact each signal reads:

| state | signal | needs_me | suggested |
| --- | --- | --- | --- |
| `archived` | `openspec.archived` names the change | no | — |
| `dropped` | the note's frontmatter has `dropped` (D35) | no | — |
| `archive-pending` | the change dir is active and (every task is ticked and `tasks_total > 0`, or the attributed PR is merged) (D33) | yes | `openspec archive <change>` |
| `conflict` | git in-progress state or unmerged files, or the attributed PR `mergeable: CONFLICTING` / `has_conflicts` | yes | `resolve, then git rebase --continue` |
| `ci-red` | any attributed check with `bucket: fail` / pipeline `failed` | yes | `/interlock:fix-tests` |
| `needs-fix` | settle `surviving > 0` with `head` equal to the checked-out commit, for the attributed change (D73), or `merge-confidence` verdict `BLOCK` for the change | yes | `/interlock:settle --review` |
| `manual-test` | `manual-test-plan.md` present and no `Result:` line and no ticked `## Next` box containing `manual test` (D34) | yes | `run the plan, add Result:` |
| `pr-open` | an attributed PR is open | iff verdict ≠ `MERGE` (D31) | `review and merge` |
| `shipped` | the last outcome for the change has `observed.commit` and there is no attributed PR | yes | `/interlock:settle --create` |
| `halted` | the latest run for the change ended in `run-halt`, or `run.json.halted` is set, or the run has neither a terminal line nor a live stage pid, or an `interrupted/` note exists for the change's latest run — `run.json`'s run when it names the change, else the newest of its notes (`at`) and outcomes (`ts`); `spokenAt` is ignored (D32, D74) | yes | `/interlock-handoff, re-run ship` |
| `shipping` | `run.json.change` is this change, the run is not closed, and the stage pid is alive; or an Escapement `running` entry | no | `wait` |
| `queued` | an Escapement `pending` entry | no | `wait or escapement list` |
| `checkpoint` | a `needs_human` row in `decisions.md`, or a review-artifacts findings file exists and `checkpoint.json` is absent or `returned` | yes | `read the spec; answer on the phone` |
| `spec-draft` | the change dir exists and nothing above matched (tasks `n/m`, `0/0` when `tasks.md` is absent) | yes | `/interlock:review-artifacts`, or `/interlock:ship <change>` when `checkpoint.json` is `approved` (D82) |

`archived` and `dropped` are read before anything else so an archived change can never be `archive-pending`, and a dropped one never returns to the board until it is archived. The table is a frozen array in `lib/facts.mjs`; the renderer's `Dial.base` `groupOrder` and `dial next`'s ordering are generated from it, so there is one priority list.

**Evidence** is a list of `{ fact, value, evidence }` rows — one per signal that was read, whether or not it matched — and is what the `## State` table prints. The matched signal's evidence is the item's `evidence` string in `dial next`.

**Attribution of the branch and its PR (D30).** The checked-out branch's PR, conflicts and checks belong to the change whose name the branch contains as a path segment or a suffix (`feat/scaffold-cli-and-registry` → `scaffold-cli-and-registry`); failing that, to `run.json.change` when the latest run names an active change; failing that, to the only active change when there is exactly one; otherwise to no change. Unattributed branch facts produce the **repo-level item** (D29): the repo note carries `state`, `needs_me` and `stale` for its branch with the states `conflict`, `ci-red`, `pr-open` and `merged` (PR merged, no change dir); a repo with no OpenSpec and no PR has `state: idle`, `needs_me: false`. There are no synthetic change notes for branches.

**Stale (D36).** `lastActivity` is the newest of: last commit date, last session, PR `updatedAt`, the newest trajectory `ts` for the change, the last outcome `ts`, the newest queue transition `ts`, the newest mtime under `openspec/changes/<change>/`, and the newest narrative entry's time. `idleDays = floor((now − lastActivity) / 86400s)`; `stale = idleDays > staleDays`; `stale` forces `needs_me: true` and the suggested action `archive, drop, or re-spec`. An item with no observed activity at all has idle days `unobserved: no activity observed` and is not stale; `next` and `brief` print `—` in its place and JSON carries `idleDays: null` (D72). The note's own `updated` never counts. `archived` and `dropped` items are never stale. Idle days live only in `dial next`, `dial brief`, `dial report` and the weekly review; a written note carries `last_activity` (the timestamp) and its date, never `<n>d`, so a quiet day rewrites nothing (D79).

**The repo view** gathers the repo-level facts for `Projects/<repo>.md`: branch, detached, dirty, stash, ahead/behind, worktrees, last commit, last session, the drift summary, the items with their states, and the three newest narrative entries across the repo's change notes (read from `notes`).

### Notes (`lib/note.mjs`, `lib/render.mjs`)

**Anatomy.** A change note is frontmatter, `## Next`, `## Narrative`, any other human-added `##` sections in their original order, then `## State  <!-- dial:generated, do not edit -->`. A repo note is frontmatter, `## Next`, `## Narrative`, then the generated `## Changes` (a table of `[[<repo>--<change>]]` wikilinks with state, needs_me and the last activity date), `## Drift`, `## Recent narrative`, `## State`. `splitNote(text)` returns `{ frontmatter, sections: [{ heading, body }] }` using `##` headings as boundaries; `joinNote` writes them back. Preserved sections are copied byte for byte; generated ones are replaced.

**Frontmatter (D19, D53).** Flat `key: value` lines in a fixed key order. Change note: `title, type: change, repo, change, scope, state, needs_me, stale, branch, pr, pr_state, ci, merge_verdict, tasks_done, tasks_total, last_commit, last_session, last_activity, created, updated, status, tags, aliases, dial_schema: dial.change/1`, plus `dropped` and `archived` when set. Repo note: `title, type: repo, repo, scope, state, needs_me, stale, branch, dirty, stash, ahead, behind, worktrees, last_commit, last_session, last_activity, active_changes, created, updated, status, tags, aliases, dial_schema: dial.repo/1`. `type: change` and `type: repo` follow the epic's note anatomy and its Bases filter, and extend the vault guide's enum through the AGENTS.md Dial section the human appends (D19). `status` is `active`, or `archived` for an archived note; `tags: [dial]`; `aliases: []`. Dial-owned keys are rewritten; `created` is written once; every key Dial does not own (`source`, a user's `aliases` edit, anything unknown) is preserved as written. `updated` is decided by rendering with the existing `updated`: equal bytes mean no write; different bytes mean `updated` becomes today and the note is rendered again (D79). A sync that changes nothing writes nothing, and every rewrite bumps `updated` as the vault guide asks. Strings containing `: `, `#` or leading special characters are double-quoted; booleans and integers are bare; the flat reader in `lib/frontmatter.mjs` is enough for every key Dial reads back.

**Filenames (D20).** `Projects/<repo>.md` and `Changes/<repo>--<change>.md`, as the epic names them; every character in `: / \ ? * " < > | # ^ [ ]` is replaced by `-`. These are slugs, not Title Case; the exception is stated in the AGENTS.md Dial section. Repo names are already unique (registry rule D4).

**Narrative (D23, D24).** `## Narrative` holds entries newest first, each `### YYYY-MM-DD HH:mm · <source>` followed by its body. Sources are the label passed to `dial handoff --source`: the default `dial handoff`, the skill's `/dial:handoff (claude)`, and `narrate`'s `local model (<model id>)`. Times are local.

**Daily line (D37).** `- HH:mm dial · <repo>/<change>: <from> → <to> (<detail>) [[<repo>--<change>]]` for a transition between two observed states, and `- HH:mm dial · <repo>/<change>: handoff (<source>) [[…]]` for a handoff. A note's first creation and an `unobserved` state are not logged.

**Summary (3.5).** `Dial Summary.md` at the vault root: frontmatter `type: note, tags: [dial], dial_schema: dial.summary/1`, then `Needs me: <n>` and one short bulleted line per needs-me item (`[[<note>]] · <state> · <last activity date>`), capped at `nextRows`; no tables, so it reads at 375 px. Its items are read from the frontmatter of every `Changes/` and `Projects/` note in the vault whose `repo` is registered there, after the sync's writes, and it is written once per vault at the end of `syncRepo`/`syncAll`, so a one-repo hook sync never drops another repo's items and needs no re-collect (D79).

**Templates.** `templates/Dial Change.md` (the `## Next` / `## Narrative` skeleton), `templates/Dial.base` (the epic's YAML with `groupOrder` generated from the state table), `templates/Dial Queries.md` (worked prompts for pi, story 6.2), `templates/AGENTS-dial-section.md` (the rules for agents over Dial notes, including the `type` enum extension and the filename exception), `templates/Daily.md` (the minimal daily skeleton: `type: daily`, `## Log`). They ship in the package and are copied by `vault init`.

**Metadata only (D57, D63).** The renderer receives facts and narrative text, never a diff or a file body. Before writing, Dial replaces secret-shaped strings in the content it writes itself — facts, evidence, narrative entries from `handoff` and `narrate` — with `[redacted]`: a word (at the start of the text or after a character outside `[A-Za-z0-9_-]`) starting `ghp_`, `glpat-`, `sk-` or `AKIA`; `Bearer ` and the next word; a word containing `password=` or `token=`; `export NAME=` and the rest of its word; a whole line containing `-----BEGIN` or `diff --git`. Bytes a human already wrote into a preserved section are copied as they are. An observed absence (no PR, no CI) is written as `none`, never as `unobserved` and never left empty (D64). Repo and change names are never redacted, so a note's name always matches its change (D84). `test/secrets.test.mjs` renders a fixture vault whose facts carry planted strings in branch names and commit subjects and greps every written file for `-----BEGIN`, `diff --git`, `Bearer `, `password=`, `token=`, `export [A-Z_]+=` and the prefixes `ghp_`, `glpat-`, `sk-`, `AKIA` at a word start only, so `risk-model` passes (D57, D84).

### Vault writes (`lib/vault.mjs`, `lib/sync.mjs`)

**Boundary.** `applyWrites(vaultPath, writes, { registry, repo })` refuses with `<repo> is registered to vault <v>; refusing to write into <path>` when `vaultPath` is not the registered vault's path for that repo, and `sync` refuses a repo whose vault path does not exist. Only `vault init`, `review` and the summary write without a repo, and only into a vault named in the registry.

**Atomic and idempotent (D38).** A file is written only when its bytes differ. A write goes to `.<name>.<pid>.tmp` in the same directory, then `renameSync` over the target; the temp file is unlinked on failure. A dotfile is used because Obsidian Sync ignores hidden files and a cross-volume rename from the Dial home could fail.

**Concurrent writers (D78).** A `dial handoff`, the PostToolUse and SessionEnd hooks, the LaunchAgent, `dial watch` and the human in Obsidian can all touch one note. Just before the rename, `applyWrites` re-reads the target and compares it with the bytes it planned from; when they differ it plans that note once more from the new bytes (so a narrative entry or `## Next` line written in between is carried into the new render), and when they differ again it skips the note with `dial: <path> changed during the write; skipped`. `appendDaily` uses the same check. A lock is not used: Obsidian takes none, so a lock would protect Dial from itself only.

**`vault init <name> [--force]` (D39).** Creates `Projects/`, `Changes/`, `Templates/`, copies `Dial.base`, `Templates/Dial Change.md`, `Dial Queries.md` and `Templates/Daily.md` when absent (`--force` rewrites them), prints one line per path with `created`, `unchanged` or `rewritten`, and prints the path of `templates/AGENTS-dial-section.md` with the instruction to append it to the vault's `AGENTS.md` by hand. It never touches `.obsidian/` or an existing `AGENTS.md`. Running it twice is byte-identical.

**`sync [<repo>] [--all] [--remote] [--due-remote] [--dry-run]` (D65).** Each repo prints `<repo>: <items> items, <needsMe> need me, <n> written`; under `--all` a repo that fails prints `<repo>: skipped, <reason>` and the run continues, ending with `dial: <k> of <m> repos not synced` and exit 1. For each repo: `collectRepo` → `readNotes` → `derive` → render every note → plan writes (`create`, `update`, `unchanged`, `append`, `move`) → `--dry-run` prints the plan and stops; otherwise `applyWrites`, then the daily lines for transitions, then one line `{ ts, vault, repo, needsMe, items }` appended to `$DIAL_HOME/logs/sync.jsonl` (the report's time series); after the last repo, `Dial Summary.md` once per vault touched. `Projects/`, `Changes/`, `Archive/Changes/` and `Daily/` are created on demand; `Dial.base` and the templates are not (D39). `--due-remote` (the agent's flag) adds `--remote` when the newest cache is older than `remoteIntervalMinutes` (D46). Transitions are detected by comparing the previous note's `state` with the new one. A change note whose change dir is gone with no archive entry is left untouched (D60).

**Daily log (D21, D22).** `Daily/YYYY-MM-DD.md` (local date) is created from `Templates/Daily.md` when present, else from Dial's skeleton; the `## Log` heading is appended when missing; lines go at the end of the `## Log` section, before the next `##` heading or at end of file; nothing above is rewritten except `updated` in the daily note's frontmatter. Dial never reads or writes `.obsidian/`; whether `daily-notes.json` points Obsidian at `Daily/` is a human step. The Obsidian CLI is not used for the append.

**Archive and drop.** On every sync, a change note with `state: archived` whose archive date is older than `archivedKeepDays` is moved to `Archive/Changes/<same name>.md` with `status: archived` and `archived: <today>` set; nothing is ever unlinked. `dial drop <repo> <change>` writes `dropped: <today>`, `state: dropped`, `needs_me: false` into the note's frontmatter and leaves the repo untouched (D35).

### `dial next` and `dial brief`

**`next [--json] [--vault <name>]` (D52).** Loads the registry, runs `collectRepo` for every repo with `remote: false` (cache only) and no subprocess but `git` (D33), derives, keeps `needs_me` items, groups them by vault, orders by the state table then `idleDays` descending, and prints `<state padded> <repo>/<change>  <idle>d  <evidence>  → <suggested>` with `[stale]` after the state when set, capped at `nextRows` rows plus `… and <n> more`. JSON is the array `{ vault, repo, change, state, stale, idleDays, evidence, suggested, note }`. Under two seconds on 21 repos is a budget, not a hope: no network, no `interlock`, five short `git` calls per repo. `brief` runs under the same rule: `git` is its only subprocess. Both resolve the repo through `resolveRepo` (below), because the hooks pass `cwd` (D69).

**Repo resolution (D69, D77).** One function, `resolveRepo(registry, arg)` in `lib/registry.mjs`, is the only place a repo argument or a working directory becomes a registry entry. A name match wins; otherwise the argument is `~`-expanded and made absolute, and matches the entry whose path equals or contains it segment by segment, comparing real paths (`realpathSync`, falling back to the lexical form when a path does not exist) and lexical paths, the longest containing path winning. `register` keeps storing `resolve(expandHome(path))`, so nothing about the registry file changes. Its consumers are `sync <repo>` (4.2, 4.5), `brief` (4.4), `handoff` (5.1), `narrate` (5.2), `drop` (4.5), `record` (5.3) and the four hook scripts (5.4), which import it in-process so an unregistered cwd still costs one registry read and no subprocess; the sessions source uses the same real path for its second slug (3.6), and the Escapement match already compares real paths (D61). The case that forces it: on macOS `$TMPDIR` is `/var/folders/…` while `process.cwd()` reports `/private/var/folders/…`, and a symlinked checkout reports its physical path to Claude Code.

**Directory roots (D18).** The registry gains an optional top-level `"roots": { "~/VSCodeProjects": "work" }`: directory (`~` allowed) → a vault name that exists in `vaults`. A path's root vault is the value of the longest root that equals or contains it segment by segment, compared through real and lexical paths with the same containment helper `resolveRepo` uses; a path under no root has none. Three places read it, all through `rootVault(registry, path)` in `lib/registry.mjs`: `register` refuses a path whose root vault differs from `--vault` (`<path> is under <root>, which belongs to vault <rv>; a repo belongs to exactly one vault`), checked before the path's existence so the refusal does not depend on the disk; the vault-write boundary in `applyWrites` (4.1) refuses every write for an entry whose root vault differs from its registered vault, which covers an entry registered before the root was declared; doctor's `boundary` check fails naming that entry, the root and both vaults. Load validation refuses a `roots` value that is not an object, a value that is not a string, and a vault name not in `vaults`, but never refuses an entry that contradicts a root, so `unregister` still works to repair one. Why prevention and not only the audit: the audit sees a mis-registration only after the first sync has written work metadata into the personal vault, and that vault syncs to the phone. Without `roots`, behaviour is exactly option A's.

**`brief <repo> [--hook] [--session <id>] [--json]` (D54).** At most `briefLines` lines: `<repo> · <branch> · dirty <n> · stash <n> · last session <ago>`; one line per active change `<state>[ [stale]] <change> — <evidence> → <suggested>` (the same ` [stale]` marker `next` prints); the newest narrative entry's heading and body; the unticked `## Next` items of the attributed change note (or the repo note); a final `dial next for everything else`. Over the cap, lines are dropped from the end in this order — Next items, narrative body, the oldest changes — and the last line becomes `… <n> more lines, see Projects/<repo>.md`. `--hook` wraps the text as the SessionStart `additionalContext` JSON; an unregistered repo prints nothing and exits 0 under `--hook` (D56) and exits 1 with `dial: <path> is not a registered repo` without it.

### Handoff, narrate, record

**`handoff <repo> [<change>] (--stdin | --text <t>) [--source <label>] [--next <text>]… [--json]` (D59).** Prepends the entry to `## Narrative` of the change note, or of the repo note when no change is given; appends each `--next` as `- [ ] <text>` to `## Next`; appends the daily handoff line; leaves the frontmatter untouched (the following `sync` bumps `updated`); prints the wikilink. Running it twice yields two dated entries.

**`narrate <repo> [<change>] --transcript <path> [--turns <n>] [--dry-run] [--json]` (D25, D26, D27).** `lib/transcript.mjs` keeps the top-level `type` `user`/`assistant` lines, drops `isMeta` and `isSidechain` lines, takes user text from string content or `text` blocks (never `tool_result`), takes assistant `text` blocks grouped by `message.id` (never `thinking` or `tool_use`), and returns the last `narrateTurns` turns. An endpoint is called only when its host is `127.0.0.1`, `localhost` or `::1`; any other host is a failed attempt with the reason `<url> is not a local endpoint`, which is how "never a cloud model" is enforced in v0.1 (D67; a LAN model host would need this rule relaxed). The endpoint is resolved from pi's `~/.pi/agent/models.json` — provider `narrate.provider` (default `mtplx`): `baseUrl`, `apiKey`, the first model id — overridden by the registry's `narrate.url`, `narrate.model`, `narrate.apiKeyEnv`; the fallback is `narrate.fallbackUrl` (default `http://127.0.0.1:11434/v1`) with `narrate.fallbackModel` (default `qwen3.6`), no key. One `POST <baseUrl>/chat/completions` with the fixed `PROMPT` and the turns, `timeout narrateTimeoutSeconds`, through an injected `fetch` (D58). The reply must contain the five labelled lines `Done:`, `Decided:`, `Next:`, `Blocked:`, `Open:`; unreachable, timeout or malformed → the fallback once → else nothing is written, stdout is `unobserved: <reason>`, exit 0. A usable reply is appended via `handoff` with the source `local model (<model id>)`. `--eval <dir>` runs over `<dir>/items/*.jsonl`, writes `<dir>/outputs/<id>.md`, and prints the score when `<dir>/labels.jsonl` (`{ id, nextCorrect, nothingInvented }`) exists (D51).

**`record --event SessionEnd|PreCompact`** (D45). Reads the hook payload from stdin (`cwd`, `session_id`, `transcript_path`, `reason`/`trigger`); a `cwd` that is not a registered repo exits 0 silently; otherwise `syncRepo`, then, unless the newest narrative entry of the attributed note covers the transcript (a handoff not older than its first `timestamp`, or narrate's own entry with no text turn after its heading's minute, so a PreCompact narration or a resume leaves the later turns to the next event), `narrate` with `transcript_path` (or `~/.claude/projects/<slug>/<session_id>.jsonl` when the path is absent). Every path exits 0; a failure is one stderr line. Record runs against a 55-second deadline inside the hook's 60: each model call's timeout is the smaller of `narrateTimeoutSeconds` and the time left minus 2 seconds, and a call with under 5 seconds left is not made (`no time left before the hook deadline`), so the hook is never killed mid-write (D80).

### The plugin (D42, D43, D44, D56)

`.claude-plugin/plugin.json` (`name: dial`, `version` equal to `package.json`, description, author, license) and `.claude-plugin/marketplace.json` (`name: dial`, `owner`, one plugin with `source: { source: github, repo: renzrollon/dial }`), installed by `/plugin marketplace add renzrollon/dial` then `/plugin install dial@dial`. `hooks/hooks.json`:

| --- | --- | --- | --- |
| SessionStart | none (every source) | `node "${CLAUDE_PLUGIN_ROOT}/hooks/brief.mjs"` | 10 |
| SessionEnd | — | `node "${CLAUDE_PLUGIN_ROOT}/hooks/record.mjs" --event SessionEnd` | 60 |
| PreCompact | — | `node "${CLAUDE_PLUGIN_ROOT}/hooks/record.mjs" --event PreCompact` | 60 |
| PostToolUse | `Bash` | `node "${CLAUDE_PLUGIN_ROOT}/hooks/sync-on-event.mjs"` | 30 |

Every hook script: read all of stdin, treat empty, malformed or TTY stdin as `{}`, resolve the repo from `cwd` (falling back to `process.cwd()`) with `resolveRepo` in-process, run the CLI as `process.execPath` + `<plugin root>/bin/dial.mjs` (the plugin root from `import.meta.url`, D42), one top-level `try`, one stderr line `dial <hook> hook error (ignored): …` on failure, `process.exit(0)` on every path, nothing on stdout except the SessionStart envelope. `brief.mjs` passes `--hook --session <session_id>`. `sync-on-event.mjs` matches `tool_input.command` against `^\s*(interlock run close|interlock settle\b|openspec archive\b)` and runs `sync <repo>`; anything else exits 0 at once. Skills call `dial` on PATH, so the global install (`npm i -g .`) stays the install path and doctor's `on-path` check says when it is missing. `skills/handoff/SKILL.md` tells the session to write the five lines, pipe them to `dial handoff <repo> [<change>] --stdin --source "/dial:handoff (claude)"` with `--next` for each next step, run `dial sync <repo>`, and end with the wikilink; it also says that under the Claude Code sandbox the vault and the Dial home must be writable from the sandbox, and that a permission failure is reported, not worked around (D83). Doctor cannot see a session's sandbox, so the check stays in the skill text, the README and H1.5. `skills/next/SKILL.md` runs `dial next --json` and renders each row with its suggested command as a drafted action.

### The agent and the watch (D46)

`lib/agent.mjs` is Escapement's `lib/agent.mjs` with the names changed: label `com.dial.sync`, plist `$HOME/Library/LaunchAgents/com.dial.sync.plist` (from `env.HOME`), `ProgramArguments: ['/bin/sh', '-c', "exec '<process.execPath>' '<bin/dial.mjs>' sync --all --due-remote"]`, `StartInterval: syncIntervalMinutes × 60`, `RunAtLoad: true`, `EnvironmentVariables: { DIAL_HOME, PATH }` (the installing shell's PATH so `git`, `gh`, `glab` and `interlock` resolve), `StandardOutPath`/`StandardErrorPath` under `$DIAL_HOME/logs/agent.{out,err}.log`, XML-escaped values. every `agent` subcommand refuses off darwin with `agent <sub> is macOS only`; `install` ensures the home and `logs/`, writes the plist, runs `launchctl bootout gui/<uid>/<label>` (result ignored) then `bootstrap gui/<uid> <plist>`, and removes the plist when bootstrap fails. `uninstall` boots out (exit 3 or 113 means not installed, still success) and removes the plist. `status` is `not-installed` without a plist, else parses `launchctl print gui/<uid>/<label>` for `state =` and `pid =` into `running` (exit 0), `loaded-not-running` (exit 1, fix `launchctl kickstart -k gui/<uid>/<label>`), `not-loaded` (1), `paths-missing` (1). `DIAL_LAUNCHCTL_BIN` overrides the launchctl path so tests use a fake binary. `dial watch` polls every `watchPollSeconds` the newest mtime under `.claude/ship/` and `openspec/changes/` of every registered repo and runs `syncRepo` for a repo whose mtime moved; it prints one line per sync and runs until SIGINT. No `fswatch`.

### Report and review (D40, D41)

`report [--json]` reads every Dial note in every registered vault, `$DIAL_HOME/logs/sync.jsonl` and the daily `## Log` lines, and prints: items by state as `<n> of <N>`; median idle days; the needs-me count per day for the last four weeks; the baseline week beside the current week, where a baseline line is `- HH:mm baseline · reorient <n>m · lookups <n>` under `## Log` (the format story 0.5 asks the human to write); the narrative source split (`/dial:handoff`, `local model`, none) across change notes; the narrative quality score from `labels.jsonl`. Every missing input is `unobserved: <reason>` with its denominator. `review --week` writes `Inbox/Dial Review YYYY-MM-DD.md` in each vault (the vault guide's default folder for a new note): `![[Dial.base#Stale]]`, the drift totals, and for each stale item three checkboxes — archive, drop, re-spec — with the command for each.

### Doctor, limits, registry, home, shell (D48, D49, D62)

**Doctor** keeps the six checks in their living order (`node`, `home`, `registry`, `obsidian-cli`, `boundary`, `permissions`) and appends, after `permissions` (D68): `vault-scaffold` (`ok` when every registered vault has `Projects/`, `Changes/` and `Dial.base`; `warn` naming the vault with fix `dial vault init <name>`); `vault-nesting` (`warn` when one registered vault path lies inside another, naming both — the `work/work` case); `narrate-endpoint` (`ok` with the resolved URL and model when pi's models file or the registry's `narrate` block configures a primary endpoint, `skip` with `no narrate endpoint configured` when only the built-in fallback would be used; no network call; the key never printed); `launch-agent` (`ok` for `running`, `skip` for `not-installed`, `warn` for the other outcomes with the status fix); `on-path` (`ok` when `dial` resolves on PATH, `warn` with fix `npm i -g .` otherwise); `fields` (always `ok`, evidence listing every frontmatter key Dial writes per note kind — change, repo, summary, daily, review — and one line naming the generated body sections and the metadata they carry, readable under `--json` since an `ok` row renders as one line, so a work repo's owner can see exactly what leaves it). `permissions` keeps its rule and stays `warn` (D9 — hooks need no allow rule; the skills do). The header rule is unchanged: `N passed` is `counts.ok`.

**Limits** adds `subprocessTimeoutSeconds` 10, `remoteIntervalMinutes` 30, `syncIntervalMinutes` 15, `narrateTurns` 20, `narrateTimeoutSeconds` 30, `nextRows` 50, `watchPollSeconds` 30, with descriptions; the registry override rule is unchanged.

**Registry** accepts an optional `narrate` object with string keys `provider`, `url`, `model`, `apiKeyEnv`, `fallbackUrl`, `fallbackModel`; a URL must start with `http://` or `https://`; an unknown key inside `narrate` is refused naming it. The schema marker stays `dial.registry/1` because the block is optional.

**Home** gains `cache/remote/<repo>.json` (the directory created by the first cache write, not by `ensureHome`), `logs/sync.jsonl`, `logs/agent.{out,err}.log`, and `eval/` for the narrative quality set (`items/` placed by the human, `outputs/` written by `narrate --eval`, `labels.jsonl` written by the human; D66). `sync` without `--dry-run`, `record` and `watch` (which sync) and `agent install` join `register`/`unregister` as the commands that create the home; `next`, `brief`, `report`, `doctor`, `vault init`, `handoff`, `narrate`, `drop` and `review` never create it. `DIAL_NOW` (an ISO-8601 date-time with `Z` or an offset; anything else is refused) overrides the clock for tests and is documented. Local dates and times follow the process `TZ`; the harness's `runCli` sets `TZ=UTC` unless a test overrides it, and every scenario printing a local time assumes it. Timestamps Dial writes into machine-read files (`sync.jsonl` `ts`, cache `fetchedAt`) are `toISOString()` form (D76).

**Shell.** Usage gains one line per new command and the `Environment:` line names `DIAL_HOME`, `DIAL_NOW`, `DIAL_LAUNCHCTL_BIN`, `ESCAPEMENT_HOME`, `ESCAPEMENT_CHECKPOINT_URL` (D50: the checkpoint URL is appended verbatim to the `checkpoint` state's evidence). `--json` is accepted by `next`, `brief`, `sync`, `vault init`, `handoff`, `narrate`, `record`, `drop`, `agent status`, `report`, `review`.

## Risks / Trade-offs

- [Interlock changes a file shape] → every reader gates on the `schema` key, skips unknown trajectory `type`s, and reports an unknown schema as `unobserved: <file> schema <x> not understood`.
- [Two writers touch one note at once — a handoff and a hook sync, or a sync and Obsidian] → re-read before rename and re-plan once (D78); the human-owned sections are the ones carried forward.
- [A killed ship looks like a running one on disk] → `shipping` requires a live stage pid; without one the run is `halted` with reason `interrupted` (D32), which is the honest reading.
- [`observed.commit` is null on a change committed by hand] → `archive-pending` is computed from the ticked tasks, not from outcomes, so such a change still surfaces (D33).
- [Twenty-one repos × subprocesses] → `next` runs only `git`, every call has `subprocessTimeoutSeconds`, and the remote cache keeps the network out of the offline path.
- [The vault guide's `type` enum and Title Case rule] → the AGENTS.md Dial section the human appends states both exceptions (D19, D20); until it is appended, a vault agent may question the notes but cannot break them.
- [Obsidian's daily note lives at the vault root until `daily-notes.json` points at `Daily/`] → a human step (H0), stated in the hand-off; Dial follows the guide, not the app default (D21).
- [Narrative order newest-first differs from the daily log's chronological append] → the daily log is the guide's rule; the narrative is Dial's own section and its readers (the brief) want the newest first (D23).
- [The local model is down or slow] → one call, one fallback, `narrateTimeoutSeconds`, exit 0 with `unobserved` (D26); the handoff skill stays the recommended path until the quality score says otherwise.
- [Hooks run in every repo] → the first thing each hook does is the registry lookup of `cwd`; an unregistered repo costs one JSON read and exits.
- [A plist bakes in `process.execPath`] → `status` reports `paths-missing` when the Node binary moved, with the fix `dial agent install`.
- [Nested vaults double-count] → doctor's `vault-nesting` warns (D62); the registry entry pins the exact root the human chooses (epic D3).
- [Thirty-one tasks and fifteen delta specs in one change] → the owner's call; the sections are ordered so each wave only needs the previous one, and the red wave is narrow enough to go green in the next section.
