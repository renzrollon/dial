# Tasks

Shape: TDD for the two pure cores. Section 1 writes the failing suites for the state machine and the renderer — the only modules whose behaviour a fixture can pin before any collector exists; section 2 makes them green; sections 3–6 are standard, each landing its own tests and docs, and each needing the previous section's output. `## H0.` and `## H1.` hold the steps only a person can take. Their lines carry `[human]` (a decision, or a step outside this repository) or `[manual]` (a hands-on check on this machine) and are tracked by neither OpenSpec nor ship — nothing ever hands one to an agent.

Known test pins this change alters, each updated in the task that changes the meaning: `test/cli.test.mjs:14` (seven commands) and `:73` (usage's last line) in 4.5; `test/cli.test.mjs:218-223` and `test/limits.test.mjs:15,58` (three caps) in 3.9; `test/doctor.test.mjs:135-146` (`DIAL OK — 5 passed`, six checks) in 6.5. The rule for any further pin: an assertion that pins a meaning the delta specs change is updated in the task that changes that meaning, never during a remediation stage, and the update names the assertion and the requirement it now pins.

Shared value: the registry's repo→vault mapping gains its first write consumers in this change. Every vault write goes through the one boundary check built in 4.1; its consumers are 4.2 (sync), 4.1 (drop), 5.1 (handoff), 5.2 (narrate, through handoff), 5.3 (record, through sync), 6.3 (review), and the hooks in 5.4 through the CLI. The registry's directory → vault `roots` map (D18) is read only through `rootVault`, built in 3.9; its consumers are `register` (3.9), the vault-write boundary (4.1) and doctor's `boundary` check (6.5). `dependsOn` edges are written as "Depends on" in each task.

Shared transform: the repo argument or working directory → registry entry (`resolveRepo`, design §Repo resolution, D77) is built once in 3.9. Its consumers, each with a task that uses it and none with its own copy: `sync <repo>` and `drop` (4.2, 4.5), `brief` (4.4), `handoff` (5.1), `narrate` (5.2), `record` (5.3) and the four hook scripts (5.4, in-process); the sessions source's real-path slug (3.6) and the Escapement match (3.5, D61) apply the same real-path rule to their own inputs.
